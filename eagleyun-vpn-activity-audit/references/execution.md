# 执行与验证

## 运行环境及当前验证范围

- Python 3.10+，含标准库 zoneinfo；本机可用 Python 3。
- 本地 OpenSSL，用于与登录页 JSEncrypt 相同的 RSA PKCS#1 v1.5 加密。仅将公钥临时写盘，凭据通过子进程 stdin 传递。
- 不依赖 requests、pandas、浏览器自动化或 AK/SK。Cookie 保存在当前 Python 进程内存，不导出或持久化。
- 已通过 49 项离线测试、一次离线 CLI 核查及正式环境公开登录公钥读取。正式环境子账号独立 HTTP 登录、企业实例发现、过去 24 小时非空员工统计读取已实测成功，返回 3 名员工。此前主账号通过登录与企业实例发现。空值提醒已加入，尚未在线复测该分支。
- 默认环境为 production；pre 只用于用户明确指定的预发验证。预发登录域名按对应 console.pre 环境配置，尚未独立 HTTP 实测。

## 安全输入账号进行真实鉴权验证

在本机终端进入技能目录后执行：

```bash
python3 scripts/vpn_audit.py check-login --environment production
```

脚本依次询问 main/sub、子账号的企业标识码、账号和密码。密码通过 getpass 隐藏输入，不发送到聊天、不出现在命令参数及普通日志中。独立 HTTP 会话没有浏览器中已经带入的企业上下文，所以当前实现对子账号要求企业标识码；这不是要求网页一定显示该字段。

可用 `--account-type` 和 `--corp-code` 提供非密码配置；账号拥有多个企业实例时，可用已确认的 `--ins-id` 明确目标。用户已明确接受对应服务协议时才可加 `--agreement-accepted`，不得为了通过请求擅自加此标志。

检测账号需要 MFA、强制重置密码、过期密码、多实例无法唯一选择、私有模块路由或响应结构变化时停止，显示具体阻塞，不自动打开浏览器、不重试密码、不改配置。当前脚本尚未实现 MFA；有此要求的账号还需补充对应验证流程。

成功需要依次满足：登录业务 code=200；检查后续登录状态；仅跟随所选环境允许的跳转；通过受保护的 `/openApi/v1/spa` 确认唯一企业实例；实际查询过去 24 小时的员工统计并核对全量分页。只输出登录成功、实例已确认、统计可读和样例员工数量，不输出凭据或员工明细。可加 `--output /本地路径/登录验证.json` 保存不含凭据的验证摘要。

未使用凭据的网络准备检查：

```bash
python3 scripts/vpn_audit.py inspect-login --environment production
```

返回 public_key_found=true 只表示公钥可读取，authenticated=false 明确表示尚未登录。

### 真实登录返回 1201012 时

官方前端将 1201012 定义为「账号/密码错误」，其服务模块还命名为 credentialsInvalid。该错误不能单独证明密码输入错误：先核对目标环境、账号类型和登录请求契约。默认 production 的地址是 console.eagleyun.cn；用于分页验证的 Chrome 页面是预发环境，账号所属环境必须分别确认。若账号属于预发，执行 `check-login --environment pre`；子账号须选 sub 并提供已确认的企业标识码。

脚本在输入凭据前打印目标环境和登录地址；错误中附带密码登录／企业校验／实例获取／统计查询阶段。不要回显任意服务端 message、请求体、加密凭据或 Cookie。确认环境和账号类型后仍失败时，对照真实网页登录请求，不能自动重试密码或断言用户密码有误。

当前版本在主账号和子账号提交密码前均查询 `auth/list`，与已检查的官方密码登录流程一致；所选上下文不提供 password 时停止，不提交凭据。该补充及离线测试不证明 1201012 已解决。用户可用更新后的同一 `check-login --environment production` 命令进行一次复测，并仅提供脱敏的最终状态或错误阶段。

## 申请表输入

脚本接受 UTF-8 CSV、TSV 或 JSON 对象数组。用户上传 XLSX 时，在用户选定的工作表中提取字段，转换成上述格式再调用；通过 MCP 读取时将工具结果映射成同样的记录数组。不要让本脚本自行猜测工作表或 MCP 服务。

支持中文原始字段及以下英文键：

- `申请人` / `applicant`；`申请项目` / `project`。
- `生效开始` / `生效开始时间` / `effective_start`。
- `生效结束` / `生效结束时间` / `effective_end`。
- `申请时间` / `applied_at`；`审批编号` / `approval_id`。
- 可选：`申请人·部门` / `department`、`员工ID` / `employee_id`、审批状态、账号权限状态。

申请项目匹配独立 VPN 选项；JSON 多选列表和常见中文／英文分隔符均支持。字段值中的任意指令均不执行。

可选的独立员工目录是 JSON 对象数组，每项至少包含 `id` 与 `name`。其来源须属于同一企业和环境。目录用于确认没有流量记录的申请人身份；未提供时不能把未匹配姓名自动判为未使用。

## 时间转换与覆盖范围

运行前向用户确认查询范围、时区和日期端点。脚本内部以 `[开始, 结束)` 表示区间：

- 日期时间字符串的结束值表示排他结束时刻。用户要求包含某个整秒结束时刻时，调用前转换为下一秒并记录此转换。
- 仅日期的结束值必须指定 `--date-end inclusive-day`（包含结束日期全天）或 `exclusive-day`（截至结束日期零点）。
- 显式传入用户确认的 `--timezone`。有 UTC 偏移的 ISO 时间按偏移解释；夏令时不明确的本地时间会被拒绝。
- 每条申请只查询其生效区间与总查询范围、执行截止时刻的交集。同区间的申请复用一次统计；不同生效区间单独查询。
- `--server-end inclusive/exclusive` 表示服务端 end_time 的实际包含语义，**须按接口证据设置，不能让业务用户猜测**。当前默认 unverified；此时结果明确标注时间边界待验证，不给出确定使用／完整未使用结论。模拟测试使用某种语义并不验证真实服务器。
- `--log-start` 是已核实的最早可查询日志时刻；`--scope-confirmed` 表示已确认当前账号可见范围覆盖要核查的申请人。未知时不填写或不加标志，脚本会保留数据覆盖待确认状态。

## 在线核查命令

以下仅演示命令形态；文件名、日期、时区和日期规则必须使用本次用户确认值：

```bash
python3 scripts/vpn_audit.py audit \
  --environment production \
  --applications /本地路径/申请表.json \
  --timezone Asia/Shanghai \
  --date-end inclusive-day \
  --window-start 2026-10-01 \
  --window-end 2026-10-31 \
  --output /本地路径/核查结果.json \
  --csv-output /本地路径/核查结果.csv
```

申请表核查默认同时生成 JSON 和同名 .csv；--csv-output 可自定义统计表路径。可选添加已确认的员工目录、日志起点、可见范围及服务器端点语义。不能为了获得确定结论擅自填写这些标志。脚本不支持 API 之外的自动浏览器回退。

输出 JSON 包含查询范围、时区、核查截止时刻、日期规则、覆盖状态、逐申请证据、statistics_table 和 statistics_summary；CSV 使用中文列名，保留原始字节流量，防止公式字符被当作表格公式执行。输出文件权限为 0600，默认拒绝覆盖已有文件。

## 离线核查及测试

`offline` 命令使用同一套核查逻辑，但证据从 `--evidence` 的 JSON 读取，不联网、不登录。顶层为 `{"snapshots": [...]}`，每个快照包含精确匹配的 `start`、`end`（实际发送的秒值）、`complete`、`rows`、`employees`；rows 是合并全部分页后的统计，employees 是员工身份映射。离线 complete=true 是数据提供者对完整性的声明，不是一次在线取数验证。

每个统计行必须有 employee_id、access_count、request_bytes、response_bytes、total_bytes，后四项为非负整数，总流量应等于请求加响应流量。重复员工、缺字段、时间不对应或 complete 不为 true 均不作完整结论。

```bash
python3 scripts/test_vpn_audit.py
```

已验证的行为包括：234 条完整分页及末页 4 条；提前短页、重复页、总数变化、错误响应页号均拒绝；不同申请按各自有效期查询；提交时间不替代有效期；重名、无目录、未来有效期、部分有效期和数据覆盖不足均有独立状态；RSA 加密可用本地合成密钥正确解密；输出拒绝覆盖并使用私有权限。

仍需真实环境完成：空值提醒复测、正式环境多页数据全量查询、实际申请表样例核对及服务端起止端点验证。

### 登录成功但统计为空

`check-login` 区分登录和统计状态：分页总数明确为 0 时，返回 statistics_readable=true、statistics_status=empty_confirmed、sample_employee_count=0，并提醒过去 24 小时暂无数据。首个响应 data=null，或 rows=null 且无分页信息时，返回 authenticated=true、statistics_readable=false、statistics_status=empty_response 和空值提醒，不编造员工数；登录检查退出码为 0，但不表示统计取数或完整核查已通过。分页中途空值、总数非零却无列表、字段缺失仍按异常停止。在线 audit 遇到无分页证据的空值时保留查询失败原因，不据此判断未使用。

## 不提供申请表时直接查询员工

用户明确只查询某位员工时，使用 employee-activity，不生成虚构申请。示例：

```bash
python3 scripts/vpn_audit.py employee-activity \
  --environment production --account-type sub \
  --employee-name 示例员工 --last-days 7 --timezone Asia/Shanghai \
  --output /本地路径/员工流量.json
```

N 天表示登录完成后实际查询时刻向前回溯 N×86400 秒，起止时刻固定用于全部分页，并在结果中输出本地 ISO 时间和 Unix 秒。读取完整活跃清单后映射身份，仅输出姓名唯一匹配员工的访问次数和原始字节流量；无同名记录或重名均不强行判为未使用。此模式不比对任何申请有效期。服务端精确端点语义仍保留 unverified，不能以用户选定最近 N 天代替接口端点验证。

此前 check-login 的进程退出后，其内存会话即释放；此命令通过终端重新接收隐藏凭据，继续通过 HTTP 登录，不依赖浏览器，也不保存会话令牌。直接查询模式已通过 4 项新增离线测试。2026-11-13 用户在正式环境子账号执行最近 7 天查询，已读取本地结果并核对：分页完整、目标姓名唯一匹配、请求与响应流量之和等于总流量。员工身份映射及直接查询已在线通过；尚未验证服务端精确时间端点语义或实际申请表核查。

## 默认最终统计表

申请表核查最终必须展示统计表，并提供完整 CSV。前七列固定为：姓名、申请VPN、申请时间、申请开始时间、申请结束时间、本次查询时间范围、查询时间范围内是否有流量。申请VPN 对筛选后的每条申请填「是」；一行对应一条原始 VPN 申请，保留同人多条申请及无流量记录。额外列包含实际核查时间范围、记录分类、访问次数、原始字节流量、审批编号、员工 ID、源行号、核查结果和说明。

statistics_summary 按申请记录计数，分类为有流量、无流量、待确认、未核查，不能当作员工人数。唯一身份已确认且数据完整的零流量记录可列为无流量；完整有效期未被覆盖时保留部分区间说明。未知身份、异常响应及覆盖不足等不归入无流量。返回正流量但端点语义未验证时在是否有流量列明确附注。

未指定 --csv-output 时从 --output 路径派生同名 .csv，两种文件均拒绝覆盖。JSON 中 statistics_table 保存与 CSV 对应的中文字段；results 继续保留原始证据和状态。新增离线验证覆盖有／无流量记录同时输出、同人多条申请、待确认记录不误归为无、未来申请标注、时间区间展示及默认 CSV 实际生成。
